## 2026-08-24 — The 3D graph "had no colour": an unrequested path, and a denser inspector

- **Reported as a rendering bug; it was not one.** Opening the graph greyed out every node except two or three. `scripts/force-graph-3d-color.test.mjs` already covered `resolveNodePaintColor` and passed — because the paint layer was correct. The defect was one layer up in `App.tsx`: an effect auto-filled the path **target** whenever it was empty, while a second effect prefilled the **source** from the active note. Two populated endpoints mean `computeGraphView` traces a real shortest path, and 3D path mode dims every off-path node to `#94a3b8` at 0.28 opacity.
- **Why it hid for so long.** 2D carries the identical bug but responds differently — it keeps community colours during path mode and paints only the path — and 2D is the default engine. Worse, the auto-fill read a *stale* `pathSourceId` (both effects run in one commit, so the second saw `""`), so it picked `graphNodes[0]`. In a vault where the active note happens to sort first, target === source and no path arms at all. The bug's visibility depended on which note you opened.
- **Reproduced before fixing.** Opening the graph from a note that was not first produced `pathResult: "Backlinks -> Home"` with zero clicks, and a render matching the report exactly: one white node, two amber, everything else grey.
- **Fix:** never invent a path endpoint. The effect now only *drops* a target that has left the visible graph. Both selects gained an explicit empty `<option>` — without one, `value=""` makes the browser display the first option as if chosen, which is the most likely reason the auto-fill was added.
- The activation rule moved to `src/graphPathRequest.ts` as `isPathRequested`. It decides whether the entire graph keeps its colours, so it earns a name and a direct test instead of living inline as a three-clause condition. See [[Decision Log]].
- **No way out of path mode** once traced (user-reported in the same pass). Added a **Reset** button in the Path header while a path is active, and clicking empty canvas now clears the path along with the selection. Named "Reset" rather than "Show all" because Communities already owns a "Show all" in the same column.
- **Inspector compacted.** The real problem was hierarchy, not spacing: Path, Connections, Hubs and Communities were all 15px — the same weight as the selected node's own title — so nothing in the column looked more important than anything else. They are micro-headers now. Labels share a line with their values; `confidence` and `degree` fold into their siblings; the idle path hint went, since both selects already say "Choose a node…". Rows 66px → 51px, Explain block 66px, Path block 104px idle.
- **Three defects the redesign exposed**, each found by rendering rather than eyeballing: "PATH" appeared twice once both became micro-headers (field label vs section header — the field is `FILE` now); "PROVENANCE" overran its label column and collided with its value; Hubs rows towered over Connections rows because Hubs uses a bare `.connectionRow` and never got the Connections-scoped 12.5px.
- **Long paths truncate on the left** via new `src/displayPath.ts`. Deliberately *not* `shortenPathForDisplay`: keeping both ends spends twelve characters on `/Users/name…`, which every row in a vault shares, while the filename is what identifies the row. Full path stays in the `title`.
- Verified in the running dev app across both themes and in an isolated static harness for the edge-selected variant (the case with the long labels). Shipped as `d307f47`.

## 2026-08-24 — Node.js becomes a prerequisite; bundled runtime removed

- Verified the CI-built 0.4.2 universal dmg and found the **bundled Node runtime was never in it**. `tauri.conf.json` packed it with the shallow glob `resources/mcp/runtime/*`, which copies only top-level *files* — so CHANGELOG/LICENSE/README shipped and `bin/node` did not. A 112MB binary in a 10.2MB dmg was never possible.
- So the "no-Node MCP kit" (headline 0.4.1 feature) never worked from an installer, on either platform. It silently relied on the user already having Node.
- Widening the glob to `runtime/**/*` then **failed the build**: `prepare-mcp-bundle` extracted Node to a temp dir and copied `bin/` preserving symlinks, leaving `corepack`/`npm`/`npx` dangling into a deleted path. That is almost certainly why the shallow form was chosen originally.
- **Decision: stop bundling Node.** It is now a user prerequisite. Removed the runtime resource, `--with-node`, `downloadNodeRuntime()`, `httpGet()`, the `mcp:bundle:node` script and the `withNode` bundle marker.
- Launchers now resolve Node as `NODEZ_NODE_COMMAND` → PATH → common installs (Homebrew, nvm, Volta, asdf, `Program Files\nodejs`), then print install guidance. The fallback matters: a client launched from Finder/Dock gets a reduced PATH. Verified live — with `PATH` stripped of Node, the launcher still found `/usr/local/bin/node` and served the vault.
- App now actually probes Node (`node --version`) instead of assuming `"node"` works, and Settings → Agents shows the version or install guidance.
- **`src-tauri/resources/mcp/` is generated**, not source: `prepare-mcp-bundle.mjs` rewrites the launchers from inline templates on every build. Editing those files directly is silently reverted — edit the generator.
- Earlier exec-bit fix re-scoped honestly: the generator has chmod'd 0755 since `30b6e0e`, so release builds were always fine. The `100644` fix only mattered for `tauri dev`, which copies the tracked file as-is.
- Local mac builds now work: it was never a missing toolchain, just `~/.cargo/bin` missing from PATH so Homebrew's x86_64 rust shadowed rustup.

## 2026-08-24 — 3D graph was exactly flat; spherical layout + fit-all

- The 3D graph was not "mostly flat", it was **exactly planar**: measured xRange 80.5, yRange 52.7, **zRange 0**.
- Cause: the node layout cache is shared with the 2D canvas engine, which writes x/y and no z. The 3D renderer seeded a missing z as 0, and a planar configuration is a **fixed point** — the z-component of every force cancels by symmetry, so the sim can never leave the plane. 2D is the default engine, so opening it first made 3D flat forever.
- Proven by control: skipping the 2D settle gave zRange 69.3; doing it gave 0. After the fix, 72.7.
- Spherical envelope added for 3D only (`src/graphRadialShape.ts`), radius ∝ cbrt(node count). 2D keeps its own tuned gravity — a radial force was tried there and reverted on request.
- Opening the graph now frames the whole graph instead of zooming into the active note; initial fit waits for engine stop.
- Release CI fixed: it had **never** completed on either platform, so 0.4.1's installers were hand-built. Windows failed a test hardcoding POSIX separators; macOS died signing updater artifacts it can never publish.
- macOS universal2 now builds green in CI. Publishing still blocked on three missing GitHub secrets (see Distribution note).

## 2026-08-20 Fixed a Main-Thread Deadlock in `pick_vault`, Verified the Watcher End to End

Real-world use surfaced a bug the build/compile checks couldn't catch: clicking "Open vault" hung the app with a spinning cursor.

Root cause (found by reading the actual crate source, not guessing): `pick_vault` was a plain (non-`async`) Tauri command, so Tauri dispatches its body synchronously on the same thread that handles the IPC call — the main thread on macOS. Inside it, `blocking_pick_folder()`'s own doc comment says it must not be called on the main thread. The main thread blocked waiting on the native panel, but showing/dismissing that panel needs the main thread's run loop free — a self-deadlock.

Fix: made `pick_vault` an `async fn`, matching the plugin's own documented usage pattern, so Tauri dispatches it off the main thread. Verified by the user: opening the vault now works.

Also verified, with the user driving the actual desktop window (something I can't automate — no tool here drives a native macOS window):

- rename and delete both work correctly on disk
- the `vault-changed` watcher reconciliation works end to end — confirmed with temporary diagnostic instrumentation (Rust-side `eprintln!` on each watcher stage, a temporary JS-side event counter) showing real fs events flow from `notify` through `app.emit` to the frontend refresh; instrumentation removed once confirmed

Phase 1 (Tauri vault) is now genuinely confirmed working end to end, not just compiling.
